# 🛰️ Satellite 更新日志

## 2026-06-04 — Round 3: 能力缺口分析

### 问题
人工分析三步找到 `amap-navigation` 候选：读 TOOLS.md → 看到 API key + 四页规范 → 发现 skills/ 无对应 Skill。Satellite 完全看不到 TOOLS.md，只能从 memory/ 碎片中盲猜。

### 根因
log_sniffer 只扫 `memory/*.md`，不读任何 workspace 文件（TOOLS.md、现有 skills/、USER.md 等）。它像只查通话记录的侦探，不了解主角的装备和已有技能。

### 改动

| 文件 | 改动 | 效果 |
|:---|:---|:---|
| `log_sniffer.py` | 新增 `sniff_capabilities()` 函数族 | 读 TOOLS.md 提取 API key 章节；扫描 skills/ 列出已有 Skill；检测"有 key 无 Skill"的能力缺口 |
| `gateway_router.py` | System Prompt 新增第 4 维度「能力缺口层」 | 缺口分析优先级最高；TOOLS.md 有 key 但无 Skill → 即使日志无痕迹也触发 suggest；不再是纯粹被动等重复模式 |
| `main_satellite.py` | 研判前注入 workspace 能力上下文 | 调用 `sniff_capabilities()`，将能力清单 + 缺口预判注入 LLM 的 extra_user_context |

### 效果
- 不再需要日志里出现 ≥3 次工具调用才能触发
- TOOLS.md 里有 `高德地图 (Amap)` API key + 完整调用规范，但 skills/ 无对应 Skill → 直接触发 `suggest`
- 从"被动找重复"变成"主动找缺口"

## 2026-06-04 — Round 2: 放宽频率阈值 + 提议模式

### 问题
Satellite 跑了 6 次周期，0 个新 Skill。三道门槛卡死产出：频率死卡"≥2天"、复杂度过滤太粗暴、信号通过 dreaming 管道衰减。

### 改动

| 文件 | 改动 | 效果 |
|:---|:---|:---|
| `gateway_router.py` | Schema 新增 `suggest` action | `Literal["merge","upgrade","suggest","ignore"]`；suggest 和 merge 一样填 target_name/description/compile_instruction，但报告里标记为"低置信度提议" |
| `gateway_router.py` | System Prompt 频率阈值放宽 | `≥2天反复出现` → `≥3次不限天数`，单日密集调用也能触发 merge |
| `gateway_router.py` | System Prompt 提议模式说明 | 2 次出现 / 工具链简单 / 把握不够 → 输出 suggest 草稿，而非直接 ignore |
| `main_satellite.py` | 流程适配 suggest | `_print_report`、`has_skill`、暂存触发条件均加入 suggest；报告区分"🤖 高置信度"和"🤔 低置信度提议" |
| `main_satellite.py` | 规则收紧 | "完全无信号时才 ignore"——suggest 是默认降级路径 |

### 效果
- 之前会直接 ignore 的弱信号 → 变成 suggest 草稿，用户可见可决策
- 不限天数的频率匹配让同日密集模式不再被漏掉
